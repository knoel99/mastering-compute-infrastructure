Notes de cours

Grille, bloc, thread

Un lancement CUDA crée une grille. La grille est l’ensemble des threads de cet appel. Elle se découpe en blocs. Un bloc est le groupe de threads qu’un SM reçoit. Le thread porte un indice et traite un élément.

Indice

L’indice vaut block_idx * threads + thread_idx. Quand l’indice atteint n, le thread ne touche pas la mémoire.

cuda.grid(1) calcule cet indice dans un kernel Numba. Pour un tableau de 10 éléments et des blocs de 4 threads, la formule donne 3 blocs. Les indices lancés vont de 0 à 11. Les indices 10 et 11 tombent hors du tableau.

Forme du kernel Numba

Numba compile un sous-ensemble de Python en kernel CUDA. Le premier appel compile. Son temps mélange la compilation et le calcul. Il mesure un second appel.

from numba import cuda

@cuda.jit
def vector_add(x, y, out):
    i = cuda.grid(1)
    if i < out.size:
        out[i] = x[i] + y[i]

Les crochets du lancement portent d’abord le nombre de blocs, puis le nombre de threads du bloc.

threads = 128
blocks = (n + threads - 1) // threads
vector_add[blocks, threads](d_x, d_y, d_out)

Le jumeau CPU parcourt les mêmes indices de bloc et de thread. Sans GPU, le script prend ce jumeau. Sur papier, ce jumeau est le corrigé.

def vector_add_cpu(x, y, out):
    threads = 128
    blocks = (x.size + threads - 1) // threads
    for block_idx in range(blocks):
        for thread_idx in range(threads):
            i = block_idx * threads + thread_idx
            if i < out.size:
                out[i] = x[i] + y[i]

Copie ou kernel

Numba appelle le CPU l’hôte et le GPU le device. cuda.to_device copie un tableau de l’hôte vers le device. copy_to_host ramène le résultat vers l’hôte. cuda.device_array alloue sur le device. Cette allocation ne copie pas les valeurs d’un tableau hôte.

La ligne qui porte [blocks, threads] lance le kernel. Le corps du kernel lit et écrit la mémoire du device. Il ne déplace pas le tableau entier entre l’hôte et le device.

S’il passe un tableau NumPy au kernel, Numba peut copier à sa place. La copie disparaît alors du texte du script. Il garde les appels explicites pour chronométrer le transport à part du calcul.

d_x = cuda.to_device(x)
d_y = cuda.to_device(y)
d_out = cuda.device_array(x.size, dtype=x.dtype)
vector_add[blocks, threads](d_x, d_y, d_out)
out = d_out.copy_to_host()

Venv du portable sur un nœud aarch64

Un venv fige l’interpréteur de la machine qui l’a créé, et les extensions compilées avec lui. Un portable x86_64 produit un exécutable x86_64. Le nœud GPU décrit dans le journal public est aarch64. Le chargeur de ce nœud refuse l’exécutable du portable. Le message usuel est exec format error. Une roue marquée pour x86_64 échoue aussi à l’import.

Il construit le venv sur la machine qui va l’exécuter. Sur le portable, le venv du portable lance le kernel si un GPU CUDA répond, et le jumeau CPU sinon. Sur un GPU de cloud peu cher, il crée un venv sur ce GPU. Sur un nœud ROMEO, il crée un environnement aarch64, et seulement une fois le compte reçu des organisateurs. Copier le dossier du venv du portable ne crée pas le compte. Le binaire copié garde l’architecture du portable.

Exercice 2. Exécuter l’addition sur le portable

Il enregistre le script suivant et le lance avec python dans le venv du portable. S’il existe un GPU CUDA et que numba-cuda est installé, le script prend le kernel. Sinon il prend le jumeau CPU. Les valeurs attendues sont 0, 2, 4, 6, 8, 10, 12 et 14.

Un GPU de cloud peu cher est une branche. Il y recrée l’environnement, puis il relance le même fichier. Un nœud ROMEO est une autre branche, une fois le compte reçu des organisateurs. Il y construit un environnement aarch64. Il n’y copie pas ce venv.

import numpy as np

def vector_add_cpu(x, y, out):
    threads = 32
    blocks = (x.size + threads - 1) // threads
    for block_idx in range(blocks):
        for thread_idx in range(threads):
            i = block_idx * threads + thread_idx
            if i < out.size:
                out[i] = x[i] + y[i]

def gpu_module():
    try:
        from numba import cuda
    except ImportError:
        return None
    if not cuda.is_available():
        return None
    return cuda

def main():
    cuda = gpu_module()
    n = 8
    x = np.arange(n, dtype=np.float32)
    y = np.arange(n, dtype=np.float32)
    if cuda is None:
        out = np.empty(n, dtype=np.float32)
        vector_add_cpu(x, y, out)
        print("cpu", out)
        return
    @cuda.jit
    def vector_add(x, y, out):
        i = cuda.grid(1)
        if i < out.size:
            out[i] = x[i] + y[i]
    d_x = cuda.to_device(x)
    d_y = cuda.to_device(y)
    d_out = cuda.device_array(n, dtype=np.float32)
    vector_add[1, 32](d_x, d_y, d_out)
    print("gpu", d_out.copy_to_host())

if __name__ == "__main__":
    main()

Projet solo

Il produit un fichier vector_add.py qui additionne deux vecteurs float32. Le kernel GPU et le jumeau CPU utilisent le même indice, block_idx * threads + thread_idx, et le même test de borne.

Le script passe par le kernel si numba.cuda importe et si un GPU répond. Sinon il passe par le jumeau CPU. Il refuse un résultat différent de x + y. Il imprime platform.machine() et le chemin pris, cpu ou gpu.

import platform
import numpy as np

def vector_add_cpu(x, y, out):
    threads = 128
    blocks = (x.size + threads - 1) // threads
    for block_idx in range(blocks):
        for thread_idx in range(threads):
            i = block_idx * threads + thread_idx
            if i < out.size:
                out[i] = x[i] + y[i]

def run_gpu(x, y, cuda):
    @cuda.jit
    def vector_add(x, y, out):
        i = cuda.grid(1)
        if i < out.size:
            out[i] = x[i] + y[i]
    n = x.size
    threads = 128
    blocks = (n + threads - 1) // threads
    d_x = cuda.to_device(x)
    d_y = cuda.to_device(y)
    d_out = cuda.device_array(n, dtype=np.float32)
    vector_add[blocks, threads](d_x, d_y, d_out)
    vector_add[blocks, threads](d_x, d_y, d_out)
    return d_out.copy_to_host()

def main():
    try:
        from numba import cuda
    except ImportError:
        cuda = None
    else:
        if not cuda.is_available():
            cuda = None
    n = 1024
    x = np.arange(n, dtype=np.float32)
    y = np.ones(n, dtype=np.float32)
    if cuda is None:
        out = np.empty(n, dtype=np.float32)
        vector_add_cpu(x, y, out)
        path = "cpu"
    else:
        out = run_gpu(x, y, cuda)
        path = "gpu"
    if not np.allclose(out, x + y):
        raise SystemExit("écart")
    print(platform.machine(), path, out[:4])

if __name__ == "__main__":
    main()

Projet de groupe

À deux. L’un prend le motif coalescé. L’autre prend le motif à pas de 32. S’il prépare seul avant la séance, il fait les deux rôles l’un après l’autre et il signe chaque décompte.

Sur papier, un warp compte 32 threads, un élément float32 compte 4 octets, et le tableau commence sur une frontière de 128 octets. La personne du motif coalescé fait lire l’élément i au thread i. La personne du motif à pas de 32 fait lire l’élément i * 32 au thread i. Chacun écrit le nombre de lignes de 128 octets touchées par ce warp.

Le décompte papier attendu est 1 ligne pour le motif coalescé et 32 lignes pour le pas de 32. Ce décompte est le modèle papier du cours.

Si un GPU CUDA est visible, chacun chronomètre son kernel après un premier lancement de compilation. Prenez n égal à 1 048 576 et des blocs de 128 threads. Notez les deux temps en secondes, à côté du décompte papier. Le portable est le chemin par défaut. Un GPU de cloud peu cher, ou un nœud ROMEO quand le compte existe, est une branche. Dans cette branche, l’environnement est créé sur place.

def coalesced_index(i):
    return i

def strided_index(i):
    return i * 32

Sur GPU, les corps deviennent out[i] = a[i] et out[i] = a[i * 32]. Le tableau du motif à pas de 32 doit couvrir l’indice i * 32.

Glossaire

epoch

Un epoch est un passage complet du jeu d’entraînement dans le modèle.

batch

Un batch est le paquet d’exemples traité avant une mise à jour des poids.

transfer learning

Le transfer learning réutilise les poids d’un modèle déjà entraîné pour une tâche nouvelle.

kernel CUDA

Un kernel CUDA est la fonction lancée par l’hôte et exécutée en parallèle sur le GPU.

warp

Un warp est le groupe de 32 threads qu’un GPU NVIDIA exécute ensemble.

SM

Un SM est le multiprocesseur du GPU qui reçoit les blocs et exécute leurs warps.

coalescence

La coalescence fusionne les lectures voisines d’un warp en peu de transactions mémoire.

HBM3

HBM3 est une mémoire empilée à haute bande passante, utilisée comme mémoire du GPU.

NVLink

NVLink est le lien NVIDIA qui relie un CPU Grace et un GPU Hopper, ou bien des GPU entre eux.

NCCL

NCCL est la bibliothèque NVIDIA qui exécute les collectives entre plusieurs GPU.

all-reduce

Un all-reduce additionne les tableaux de tous les ranks et renvoie le résultat à chacun.

rank

Un rank est l’entier qui identifie un processus dans un groupe de communication.

DDP/FSDP

DDP garde une copie entière du modèle sur chaque rank, et FSDP répartit les paramètres entre les ranks.

Spack

Spack construit un logiciel scientifique et ses dépendances dans un environnement isolé.

Slurm

Slurm choisit des nœuds libres et y démarre le job.

TPE

Anticipé. TPE choisit le prochain essai à partir d’un modèle des essais déjà observés.

Hyperband/ASHA

Anticipé. Hyperband et ASHA arrêtent tôt les essais faibles et reportent le budget sur les essais qui restent.
