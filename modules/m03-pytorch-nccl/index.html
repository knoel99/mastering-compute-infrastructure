PyTorch distribué et NCCL

Objectifs

Il entraîne déjà de petits modèles. Il sert déjà des LLM. Le job sur plusieurs nœuds est nouveau pour lui. Les 18 heures servent à tenir ce premier job, à deux processus, et à lire l’all-reduce qui réunit les gradients.

Au bout du module, il fait cinq choses.

  1. Il lance un processus par GPU et il lit RANK, LOCAL_RANK et WORLD_SIZE.
  2. Il calcule la moyenne d’un gradient après l’all-reduce, sur l’exemple à quatre lignes.
  3. Il enveloppe un petit modèle avec DistributedDataParallel. Le portable utilise gloo et un tenseur CPU. Un GPU visible, avec MCI_BACKEND=nccl, utilise NCCL.
  4. Il reconnaît un blocage et il le sépare d’un pas lent.
  5. Il chronomètre un all-reduce. Un tenseur GPU passe par torch.cuda.Event. Un tenseur CPU passe par time.perf_counter.

Notes de cours

Un processus pour chaque GPU

DistributedDataParallel exécute une copie du script par GPU. Chaque copie est un processus, avec son propre interpréteur. Servir un LLM reste un processus. L’entraînement de ce module en lance un par GPU.

Sur un nœud à quatre GPU, il lance quatre processus. Chacun en voit un. Sur le portable, le laboratoire lance deux processus même s’il n’y a aucun GPU. Ces deux processus tiennent le rôle des deux GPU, sur le CPU, pour que l’all-reduce soit réel.

NCCL demande qu’un processus ait l’usage exclusif de chaque GPU qu’il touche. La documentation de torch.distributed prévient qu’un GPU partagé entre processus peut mener à un interblocage ou à un usage NCCL invalide. Un processus par GPU évite ce partage.

La fiche nomme aussi le parallélisme de modèle, le découpage du modèle en morceaux. Le script de cette page laisse le modèle entier sur chaque rang, avec une ligne d’entrée différente. Le découpage d’un LLM plus grand qu’un GPU est hors de cette page.

Trois variables pour situer le processus

RANK est l’indice du processus dans le job. Il va de 0 à WORLD_SIZE moins un. WORLD_SIZE est le nombre de processus du job. LOCAL_RANK est l’indice du processus sur le nœud. C’est lui qui choisit le GPU.

Sur un seul nœud et deux processus, LOCAL_RANK vaut RANK. WORLD_SIZE vaut 2.

Sur deux nœuds et deux processus par nœud, WORLD_SIZE vaut 4. RANK vaut 0, 1, 2 ou 3. LOCAL_RANK vaut 0 ou 1, et il recommence à 0 sur chaque nœud. Le GPU se choisit avec LOCAL_RANK.

torchrun écrit les trois variables, plus MASTER_ADDR et MASTER_PORT. init_process_group les lit quand aucune autre méthode n’est passée. Cette méthode par défaut s’appelle env://. La documentation la décrit dans la page citée en sources.

srun écrit SLURM_PROCID, SLURM_LOCALID et SLURM_NTASKS. Le fichier Python ne change pas. Le lanceur copie ces trois valeurs dans RANK, LOCAL_RANK et WORLD_SIZE, et il fournit aussi MASTER_ADDR et MASTER_PORT.

Ce que la somme écrit sur le gradient

All-reduce Chaque rang entre avec un tenseur de même forme. L’appel remplace le tenseur de chaque rang par la réduction de tous. all_reduce somme par défaut.

L’exemple tient en quatre lignes.

rang 0  [1, 3]
rang 1  [5, 7]
somme   [6, 10]
moyenne [3, 5]

Le rang 0 apporte [1, 3]. Le rang 1 apporte [5, 7]. La somme est [6, 10]. Chaque rang reçoit cette somme. La moyenne est cette somme divisée par WORLD_SIZE, donc [3, 5].

all_reduce s’arrête à la somme. DDP entraîne avec la moyenne. Le script manuel divise donc par WORLD_SIZE après l’appel. Pendant backward, DDP fait cette division lui-même. Les deux chemins doivent laisser la même valeur sur chaque rang.

Même gradient Après la division par WORLD_SIZE, chaque rang détient le même gradient. Un SGD déterministe, parti des mêmes poids, écrit alors les mêmes poids au pas suivant.

Le script qui tourne sans GPU

Le fichier s’appelle labo.py. Le chemin du portable est le défaut. MCI_BACKEND absent, ou égal à gloo, sélectionne gloo et un tenseur CPU. Un portable qui a déjà un GPU reste sur ce chemin. Le laboratoire du portable ignore ce GPU.

La branche nccl s’ouvre seulement si MCI_BACKEND vaut nccl et si un GPU est visible. Le tenseur est alors sur le GPU d’indice LOCAL_RANK. DistributedDataParallel reçoit device_ids dans ce seul cas. Sur CPU, l’appel omet device_ids.

import os
import time
from datetime import timedelta

import torch
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP


def choose_device():
    use_nccl = os.environ.get("MCI_BACKEND", "gloo") == "nccl"
    if not use_nccl:
        return torch.device("cpu"), "gloo"
    if not torch.cuda.is_available():
        raise SystemExit("MCI_BACKEND=nccl demande un GPU visible.")
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)
    return torch.device("cuda", local_rank), "nccl"


def time_allreduce_ms(tensor):
    if tensor.is_cuda:
        # Une roue CPU lève une erreur si on construit Event sans GPU.
        start = torch.cuda.Event(enable_timing=True)
        end = torch.cuda.Event(enable_timing=True)
        start.record()
        dist.all_reduce(tensor)
        end.record()
        end.synchronize()
        return start.elapsed_time(end)
    t0 = time.perf_counter()
    dist.all_reduce(tensor)
    return (time.perf_counter() - t0) * 1e3


def main():
    device, backend = choose_device()
    timeout_s = int(os.environ.get("MCI_TIMEOUT_S", "20"))
    dist.init_process_group(backend=backend, timeout=timedelta(seconds=timeout_s))
    rank = int(os.environ["RANK"])
    local_rank = int(os.environ["LOCAL_RANK"])
    world = int(os.environ["WORLD_SIZE"])
    if dist.get_rank() != rank or dist.get_world_size() != world:
        raise SystemExit("RANK ou WORLD_SIZE diverge du process group.")
    # flush=True, sinon un blocage garde la ligne dans le tampon.
    print(
        f"RANK={rank} LOCAL_RANK={local_rank} WORLD_SIZE={world} backend={backend}",
        flush=True,
    )
    if world != 2:
        raise SystemExit("Ce laboratoire attend WORLD_SIZE=2.")

    local = torch.tensor([1.0, 3.0] if rank == 0 else [5.0, 7.0], device=device)
    reduced = local.clone()
    skip_raw = os.environ.get("MCI_SKIP_RANK")
    skipping = skip_raw is not None and rank == int(skip_raw)
    if skipping:
        print(f"saute {rank}", flush=True)
        time.sleep(timeout_s + 5)
    else:
        print(f"entre {rank}", flush=True)
        dist.all_reduce(reduced, op=dist.ReduceOp.SUM)
        print(f"sort {rank}", flush=True)
        mean = reduced / world
        print(f"moyenne {rank} {mean.tolist()}", flush=True)

    if skip_raw is None:
        model = torch.nn.Linear(2, 1, bias=False)
        with torch.no_grad():
            model.weight.copy_(torch.tensor([[1.0, 1.0]]))
        model.to(device)
        if device.type == "cuda":
            model = DDP(model, device_ids=[local_rank])
        else:
            model = DDP(model)
        row = [1.0, 0.0] if rank == 0 else [0.0, 3.0]
        loss = model(torch.tensor([row], device=device)).sum()
        loss.backward()
        grad = model.module.weight.grad.detach().cpu().tolist()
        print(f"gradient {rank} {grad}", flush=True)
        elapsed_ms = time_allreduce_ms(torch.ones(8, device=device))
        if rank == 0:
            print(f"all_reduce_ms {elapsed_ms:.3f}", flush=True)

    dist.destroy_process_group()


if __name__ == "__main__":
    main()

Chemin du portable choose_device renvoie ensemble le device et le backend. Le défaut est le CPU avec gloo. Le GPU avec nccl n’existe que dans l’autre retour. Un tenseur CPU ne part donc pas vers NCCL.

La commande du portable est la suivante.

torchrun --nproc_per_node=2 --master_port=29531 labo.py

Si le nom torchrun est absent du PATH, le même lanceur s’appelle ainsi.

python3 -m torch.distributed.run --nproc_per_node=2 --master_port=29531 labo.py

Les deux rangs impriment backend=gloo, le texte [3.0, 5.0] après moyenne, et le texte [[0.5, 1.5]] après gradient. Le rang 0 imprime aussi all_reduce_ms. Deux processus peuvent coller deux textes sur la même ligne. Le critère est la présence de ces textes, dans n’importe quel ordre.

Sans torchrun, python3 labo.py s’arrête dans init_process_group. L’erreur contient environment variable RANK expected, but not set et elle nomme env://. Le lanceur est obligatoire.

Si MCI_BACKEND=nccl alors qu’aucun GPU n’est visible, chaque processus s’arrête avec MCI_BACKEND=nccl demande un GPU visible. Le message peut apparaître deux fois, une fois par processus.

La branche avec nccl

Le fichier reste labo.py. Sur une machine ou une allocation dont les GPU sont visibles, torchrun écrit déjà les cinq variables.

MCI_BACKEND=nccl torchrun --nproc_per_node=2 --master_port=29531 labo.py

Si le compte cluster existe, srun lance le même fichier. srun écrit SLURM_PROCID, SLURM_LOCALID et SLURM_NTASKS. La commande ci-dessous les copie dans RANK, LOCAL_RANK et WORLD_SIZE. MASTER_ADDR est le nom du nœud qui porte le rang 0. Sur un seul nœud, hostname suffit. Sur deux nœuds, 127.0.0.1 reste dans le nœud local.

export MASTER_ADDR="$(hostname)"
export MASTER_PORT=29531
export MCI_BACKEND=nccl
srun --ntasks=2 --gpus-per-task=1 bash -c 'export RANK="$SLURM_PROCID" LOCAL_RANK="$SLURM_LOCALID" WORLD_SIZE="$SLURM_NTASKS"; exec python3 labo.py'

Le drapeau qui demande les GPU dépend du site. S’il est refusé, le fichier Python reste le même. La demande de GPU est celle indiquée avec le compte. Les tenseurs du script fixent moyenne et gradient. Sur la branche nccl, la ligne backend vaut nccl.

Un GPU loué, sans compte cluster, reprend la commande torchrun de cette section.

Un rang qui n’entre pas

Un all-reduce et un barrier sont des collectifs. L’appel se termine quand chaque rang y est entré. Si un rang saute le collectif, les rangs qui sont entrés attendent.

Le script le montre avec MCI_SKIP_RANK. Le rang dont l’indice est cette valeur imprime saute et n’appelle pas all_reduce. Les autres impriment entre, appellent all_reduce, et n’impriment sort que si l’appel revient.

La documentation de init_process_group indique un délai de 10 minutes pour NCCL et de 30 minutes pour les autres backends, dont gloo. Avec ce délai long, un blocage ressemble à un job encore vivant. Le script passe timeout à init_process_group. MCI_TIMEOUT_S vaut 20 secondes par défaut. Au laboratoire, 8 flottants sur CPU reviennent bien avant 20 secondes. Un silence jusqu’à ce délai est un blocage.

Un pas lent imprime entre sur chaque rang, puis sort sur chaque rang. Le temps entre les deux est la durée du pas. all_reduce_ms est cette durée pour la sonde, en millisecondes.

Un blocage imprime entre seulement sur les rangs qui sont entrés, et il n’imprime pas le sort correspondant. Le rang qui a sauté imprime saute et il n’imprime pas entre.

Avec MCI_SKIP_RANK=1, le rang 1 imprime saute 1. Le rang 0 imprime entre 0. Aucun des deux n’imprime sort. Gloo lève alors une RuntimeError dont le texte contient Timed out waiting et le délai choisi. torchrun envoie ensuite SIGTERM au rang qui a sauté. Le code de sortie du lanceur est 1.

flush=True sert à voir entre avant l’attente. Sans flush, le tampon peut garder cette ligne, et le blocage ressemble à un processus qui n’a rien démarré.

Deux horloges pour un collectif

time_allreduce_ms chronomètre un all-reduce de 8 flottants, après le backward. init_process_group a déjà rendu la main. Le nombre commence après le démarrage du job.

Sur un tenseur CUDA, l’all-reduce NCCL rend la main avant la fin du travail sur le GPU. time.perf_counter autour de l’appel s’arrête au lancement. torch.cuda.Event enregistre sur le flux GPU. end.synchronize attend la fin. elapsed_time renvoie des millisecondes.

Sur un tenseur CPU, gloo bloque jusqu’à l’écriture du résultat. time.perf_counter autour de l’appel est alors la durée. Le script multiplie par 1e3 pour imprimer aussi des millisecondes.

Le test tensor.is_cuda choisit l’horloge. Le chemin CPU ne construit pas torch.cuda.Event. Une roue installée sans GPU lève Tried to instantiate dummy base class Event.

Un barrier se chronomètre avec les mêmes deux horloges, autour de dist.barrier. Le laboratoire chronomètre un all-reduce, parce que c’est l’appel qui porte la somme du gradient.

Il rend labo.py et la sortie d’une exécution sur le portable.

Projet de groupe

Deux personnes. Une seule commande, lancée par la personne B.

La personne B injecte le rang qui saute le collectif. Elle exporte MCI_SKIP_RANK=1. Elle fixe MCI_TIMEOUT_S=8, en dessous des 20 secondes du script.

MCI_SKIP_RANK=1 MCI_TIMEOUT_S=8 torchrun --nproc_per_node=2 --master_port=29531 labo.py

La personne A laisse la personne B lancer la commande. La personne A lit les lignes du rang 0. La personne B lit les lignes du rang 1. Les textes entre, saute et sort comptent même s’ils partagent une ligne. Le code de sortie 1 est la fin attendue de cette commande.

Ensemble, ils écrivent le symptôme. Cinq phrases, plus la sortie brute.

  1. La ligne que le rang 0 a imprimée, et la ligne sort qui manque.
  2. La ligne que le rang 1 a imprimée, et la ligne entre qui manque.
  3. Le texte de l’erreur qui contient Timed out waiting et le délai.
  4. Ce que le lanceur a fait au processus qui a sauté, y compris le signal.
  5. Pourquoi ce n’est pas un pas lent. Un pas lent imprime entre puis sort sur les deux rangs. Ici, sort n’apparaît sur aucun rang.
